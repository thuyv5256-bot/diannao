## 三、WARNING — 能运行但现场存在风险

### W1. LLM 稳定性：ai_factors 有 0.05 级微抖

同一暴雨场景连调 3 次 DeepSeek：

| 层级 | 结果 | 证据 |
|------|------|------|
| L1 事件识别 | **PASS** | source/model/key/level 三次完全一致 |
| L2 ai_factors | **WARNING** | 冷饮等 5 品类：`[0.7, 0.7, 0.75]`，极差 0.05；烘焙品类 3 次里只出现 1 次 |
| L3 最终补货 | **PASS** | **0/50 SKU 波动**，三次逐位一致（成本/毛利/民生/件数全同） |

**这是本项目的加分项**：安全边界 + R³ 优化器把小波动吸收了。答辩时的正确说法是
「LLM 的语义理解有 ±0.05 的固有随机性，但经过三重夹紧和整数优化后，**最终补货结果逐位可复现**」。

### W2. LLM 响应延迟（最大现场风险）

| 环节 | 3 次实测 | 均值 |
|------|----------|------|
| `ai_events.parse` | 1.62s / **16.17s** / 2.01s | 6.60s |
| `ai_insight.analyze` | 3.85s / 3.81s / 4.08s | 3.91s |
| `policy.build_plan`（无 AI） | — | **0.32s** |
| UI 渲染（15 万字符） | — | **0.002s** |

**最坏情况 20.25 秒。** 根因：
- `LLM_TIMEOUT = 8`（`config.py:111`）
- `llm.chat_json` 对 `json_mode=True` 失败会**再重试一次**（`llm.py:117-126`）→ 最多 16s
- 复杂事件（如「暴雨下雪+四十度高温+空调坏了」）输出被 `max_tokens` 截断 → `_extract_json` 失败 → 触发重试

**现场后果**：评委输入复杂事件时页面空白近 20 秒，会以为卡死。

### W3. 洞察层越权文本未过滤（不构成数值风险，但会被质疑）
