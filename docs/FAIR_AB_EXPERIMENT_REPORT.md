### 潜在需求的统一定义

```python
potential_demand = CSV.sales              # 仿真生成的潜在消费需求（上帝视角，决策层不可见）
sold             = FEFO_sell(batches, potential_demand)   # 各算法自己的库存决定能卖多少
stockout         = max(0, potential_demand - sold)        # 缺货由算法自己的库存产生
```

**不使用 CSV 里预生成的 `stockout`** —— 前置审计已证明它恒为 0（CSV 根本没有断货字段），
用它会让缺货在数学上不可能发生。

## 三、指标公式

```
经营毛利 gross_profit = Σ(实销 × (售价 − 成本)) − Σ(报损 × 成本)
```
**这是「经营毛利」，不是净利润。** 不含资金占用成本、房租、人工、跌价。
因此实验**强制同时报告**：

```
平均库存金额 average_inventory_value = 每日期末库存成本金额的平均值
期末库存金额 ending_inventory_value  = 最后一天期库存成本金额
```

**为什么要强制报告这两个**：防止算法靠「大量囤货」把服务水平刷高。
本次实验中小满的库存占用确实更高（+7.9%），这正是必须暴露的代价。

其他公式：
```
缺货率       = 未满足需求量 / 潜在需求总量
民生缺货率   = 民生品未满足需求量 / 民生品潜在需求总量
损耗成本     = Σ(报损件数 × 成本价)
预算使用率   = 采购金额 / (每日预算 × 天数)
```

> 「民生保障率」是**方案口径**（小满有该约束、传统没有），不作为算法优劣依据；

### 如实保留的不利结果

- **传统在 3 项上更优**：采购金额（少 5.2%）、平均库存占用（少 7.9%）、损耗（0 件 vs 1 件）
- 小满的缺货率虽然大幅下降，但**代价是多占了库存资金**——这不是免费的改进
- 传统策略的 `民生保障率 = 0` 是因为它根本没有这个约束，不是"保障率为 0 的算法"

## 五、消融实验（拆解各设计点贡献，不作为主结论）

| 策略 | 总缺货率 | 民生缺货率 | 民生保障率 | 经营毛利 | 收入 |
|---|---|---|---|---|---|
| 传统补货（目标库存法） | 5.78% | 5.06% | 0.0% | 148062 | 450740 |
| Forecast only（无 R³/民生/事件） | 2.25% | 1.54% | 97.0% | 154734 | 469489 |
| Forecast + R³（无民生/事件） | 2.22% | 1.42% | 98.1% | 155203 | 472076 |
| Forecast + R³ + 民生约束 | 2.24% | **1.37%** | 100.0% | 155314 | 473204 |
| 小满 − Memory | 2.24% | 1.37% | 100.0% | 155314 | 473204 |
| 小满（完整） | 2.24% | 1.37% | 100.0% | 155314 | 473204 |

### 消融的诚实解读

1. **最大改善来自 Forecast 本身**（缺货率 5.78% → 2.25%，降幅 61%）。
   传统规则只看"最近 7 天平均销量 × 3 天"，而 Forecast 有指数衰减加权、星期效应、
   节日因子、断货日需求还原 —— 预测更准，缺货自然更少。
2. **R³ 的贡献很小**（总缺货 2.25% → 2.22%，仅 0.03pp）。**这一点必须如实说明**，
   不能把 R³ 说成主要功臣。
3. **民生约束的价值体现在民生维度**：民生缺货率 1.42% → 1.37%，
   保障率 98.1% → 100%。对总缺货率甚至略有上升（2.22% → 2.24%，
   因为预算被民生锁住后其他品少了 2 件）。
4. **Memory 在 180 天尺度上没有可测差异**（小满 − Memory 与小满完整逐位相同）。
   原因：Memory 学的是「预测残差」，而 Forecast 已吸收了大部分可解释的波动，
   剩下的残差很小（主实验 `diannao` 累积 645 条经验，但 `memory_delta` 影响有限）。
   **这是真实结果，不应隐藏。**

## 十、遗留问题（如实列出，本轮未修）

### 1. Memory 反馈量过大

`eval_fair_ab.py` 给**所有策略**都开了 `process_feedback`，导致：
- `traditional` 累积 **1884 条** experience（它根本不用 Memory）
- `diannao` 累积 **645 条**

不影响公平性（各自独立隔离库），但：
- 框架不够干净（传统策略不该写 Memory）
- 是上面那个测试失败的间接原因

### 2. R³ 的贡献在总缺货率上仅 0.03pp

消融显示 R³ 的总缺货改善几乎不可见（2.25% → 2.22%）。
**不要在答辩中说 R³ 是缺货改善的主要来源** —— 数据不支持。
R³ 的价值应从「多目标可解释求解」「韧性缺口显式建模」这些设计层面讲。

### 3. Memory 在 180 天尺度无可测差异

「小满 − Memory」与「小满完整」逐位相同。真实原因见消融解读第 4 点。

### 4. 主表「谁更优」列曾出现方向错误

第一版我把 `delta = A − B` 标成了「B 的优劣」，导致优劣列全部反转。
已修正为 `delta = B − A` 并重新渲染。本报告表格是修正后的版本。
